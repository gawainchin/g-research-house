# What Changed and Market Watch Spec

> Implementation spec for turning G Research House into a living research surface: article-to-cluster backlinks, a recurring What Changed page, and ticker movement context for mentioned securities.

## Goals

1. **Close the reading loop**
   - Theme pages already link cluster → article.
   - Articles should now link article → cluster so each note feels part of a living thesis thread.

2. **Publish research deltas, not just essays**
   - Overnight Obsidian passes already produce `What Changed` synthesis.
   - The public site should expose a curated, static `What Changed` surface with thesis-level changes and follow-up actions.

3. **Add market context for mentioned tickers**
   - Financial readers need a quick place to see how referenced securities have moved.
   - This should be a delayed static snapshot, not a live trading terminal.

## Non-goals

- No brokerage/trading integration.
- No real-time websocket prices.
- No client-side Yahoo credentials/API calls.
- No direct Obsidian vault sync yet.
- No investment recommendation framing.

## Routes

### `/what-changed`

Purpose: show the latest curated research deltas from the overnight synthesis pipeline.

Render:
- title, update date, source note, summary
- entries grouped by thesis/cluster
- each entry includes:
  - status / direction
  - what changed
  - thesis impact
  - expression impact
  - follow-up
  - link to cluster page when available

### `/markets`

Purpose: show delayed price movement context for tickers mentioned across G Research House notes.

Render:
- snapshot timestamp and source/disclaimer
- ticker cards/table grouped by theme
- price, currency, 1D, 5D, 1M, YTD moves, market cap if available
- associated article links
- clear educational/delayed-data language

### Article pages

Add a compact `Research cluster` module after the article header / before the research graph or footer:
- "Part of this research cluster"
- cluster title/status/conviction
- cluster thesis
- link to `/themes/<slug>`

## Data model

### `data/what-changed.json`

```ts
interface WhatChangedData {
  title: string
  updated: string
  sourceNote: string
  summary: string
  entries: WhatChangedEntry[]
}
```

### `data/market-watch.json`

Generated by `scripts/update-market-data.py` using yfinance. The ticker universe lives in `data/market-watchlist.json`; edit that file instead of changing the fetcher logic.

```ts
interface MarketWatchData {
  title: string
  updated: string
  source: string
  summary: string
  tickers: MarketTicker[]
}
```

Each ticker includes:
- symbol, name, theme
- watch reason: concise editorial rationale for why the ticker belongs on the monitor
- auto-link keywords: ticker/name/theme terms used to discover related research notes at render time
- price/currency
- 1D, 5D, 1M, YTD percentage changes
- market cap when available
- manual article slugs plus automatically inferred related research links
- `dataOk` and `error` so failures render honestly

## Validation

Extend `npm run validate:data` to check:
- What Changed entries reference valid cluster slugs when provided.
- What Changed entry links reference existing articles if present.
- Market ticker article slugs reference existing articles.
- Required fields exist.

## Update workflow

1. Overnight synthesis creates candidate changes.
2. Hermes curates `data/what-changed.json`.
3. `python3 scripts/update-market-data.py` refreshes `data/market-watch.json` from `data/market-watchlist.json`.
4. Run:
   - `npm run validate:data`
   - `npm run build`
5. Push static snapshot.

Automation:
- `.github/workflows/refresh-market-watch.yml` runs on weekdays at `22:30 UTC` and can also be triggered manually with `workflow_dispatch`.
- The workflow installs Node/Python dependencies, runs `npm run refresh:markets`, and commits `data/market-watch.json` only if the snapshot changed.

Shortcut:

```bash
bash scripts/refresh-market-watch.sh
```

Python dependency:

```bash
python3 -m pip install -r requirements.txt
```

## UX stance

Keep the visual language editorial, not Bloomberg-terminal. The price view is context for research expression, not a trading screen.
